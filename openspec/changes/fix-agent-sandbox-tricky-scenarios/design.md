# Design

## Context

真实 8878 Pi Host 使用 `brain` 模式执行 50 个中文多轮场景。当前运行表明，
“再往上调 50”在语义抽取缺少稳定恢复时会直接进入 Pi 兜底；同时，连续单会话
中的取消动作需要与成功事实保持不同的对话焦点。

## Approach

1. 先为增量续问建立最小集成回归，证明已执行的 `api.gateway` 结果后输入增量值
   会重新生成 `awaiting_confirmation`，且合并值为基线加增量。
2. 在现有结构化续问恢复边界内补齐当前轮增量参数的识别与命名字段合并，禁止
   通过 Response Model 文本或 Pi pass-through 授权执行。
3. 为取消结果的即时对话焦点补充回归；对已验证的列表事实，在运行时边界内完成
   序号与条件筛选，避免把确定性事实运算交给回复模型重复猜测。
4. 以一个持续的 `piSessionId` 运行附件 50 场景；场景 14 的“前两个都重跑”
   按预期逐个确认，场景 50 保留 pending 竞态输入，结束后再核对无第二个确认框。

## Risks and Mitigations

- 真实模型输出有波动：用 runtime route/state 证据和最小复现区分模型偶发不稳定与
  确定性运行时缺陷，并对失败场景重复验证。
- 单会话会自然积累历史：报告中标注单会话前提，不把清单原本要求新会话的差异伪装
  成独立场景通过。
- 增量值涉及加法、百分比、单位和小数：只允许已声明 Schema 字段接收，所有新动作
  仍必须经过原有确认策略。
