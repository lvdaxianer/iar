# Proposal

## Why

沙箱逐轮语义抽取没有获得同一会话的先前操作事实，用户追问已有结果时可能误触发新操作。现有压缩结果未接入逐轮模型上下文，部分回复调用依赖聊天原文，且服务使用共享会话实例。

## What Changes

- 为每个会话维护隔离、实时更新的行为状态、可追溯操作事实和压缩摘要，构成有界模型上下文。
- 从可信事件与可公开输出契约构造跨业务事实，结合本轮问题交给模型理解；对已有结果的追问不得误触发副作用，事实不足或目标不明确时澄清。
- 为不确定路由提供基于已有事实的通用模型兜底；无明确新操作意图时不得默认执行高风险动作。
- 复用上下文压缩、保留失败时的可信状态，并避免向模型发送历史聊天原文。
- 保持 JEV 和意图模型的有限候选与一致返回契约，覆盖流式和非流式链路。
- 更新 docs 下的技术方案并补充端到端回归测试。
- 拆分已有的超长沙箱会话和模型提供器，维持公开接口与行为不变。
- 补齐沙箱入口和模型 HTTP 调用的安全审计、链路追踪及受控动态调试能力，不记录模型输入、输出或凭据。

## Capabilities

### New Capabilities

- `structured-model-context`: 定义可追溯、受限的跨轮模型上下文以及历史结果查询行为。

### Modified Capabilities

无。

## Impact

影响沙箱会话管理和接口、模型适配器、上下文压缩与事件投影、测试及 docs 技术方案；兼容原有客户端，不改变 JEV 与意图模型的现有决策返回契约。
