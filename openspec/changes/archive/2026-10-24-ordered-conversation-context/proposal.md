# Proposal

## Why

当前会话把有限的原始消息、已验证业务事实和模型对历史指代的理解放在同一层里，导致“上一个问题”和“上一个工单”无法稳定区分，序号引用也可能跨越错误的对象集合。刷新后虽然能够恢复部分消息和事实，但模型仍可能因缺少明确的有序上下文而重复发起动作或回答错误轮次。

## What Changes

- 增加有界、可恢复的对话轮次记录；一轮由一次用户输入及其最终助手回复组成。
- 保持 `factHistory` 作为独立的有序业务事实链，不把对话轮次混入业务事实。
- 扩展历史引用协议，允许模型声明引用对话轮次或业务事实，并由 Runtime 校验目标 ID、序号、关系和范围。
- 向语义抽取和回复模型分别提供带稳定序号、稳定 ID 和当前焦点的结构化对话上下文与事实上下文。
- 移除对历史引用和上下文回答的固定业务关键词依赖；模型负责理解自然语言，Runtime 只负责边界校验、权限和执行门禁。
- 保持历史原文有界、非权威；上下文引用、工作流事件和 Function 执行仍由结构化契约控制。

## Capabilities

### New Capabilities

- `ordered-conversation-context`: 提供可恢复、有序、独立于业务事实链的对话轮次上下文。

### Modified Capabilities

- `structured-model-context`: 模型上下文新增有序对话轮次、事实链焦点和按范围校验的历史引用。
- `behavior-state`: 行为状态持久化并重放有界的对话轮次焦点和引用元数据。

## Impact

- 影响 `@iar/contracts` 的 BehaviorContext、语义引用和模型输入契约。
- 影响 Runtime 的上下文投影、历史关系解析和语义提示词构造。
- 影响 Agent Sandbox 的普通/流式会话编排、消息持久化和回复上下文。
- 影响 SQLite/外部 Persistence Provider 的会话快照兼容性及回放测试。
- 不新增外部 API；现有 Function、Plugin、确认、策略和副作用执行边界保持不变。
