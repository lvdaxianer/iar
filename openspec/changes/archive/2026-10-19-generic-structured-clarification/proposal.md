# Proposal

## Why

当前会话可以把动作结果显示给用户，但没有把所有可追问的业务事实和模型生成的澄清选项保存为结构化上下文。用户在后续输入“我第几位”“1”或其他短指代时，模型看不到事实与选项，只能把它当成新问题，导致重复澄清或错误路由。

需要把这类能力抽象成与业务无关的会话机制，让任何插件都能显式公开可追溯事实，让模型在下一轮结合待澄清状态继续理解，并在 SQLite 恢复和压缩后保持一致。

## What Changes

- 将可信事实从核心代码固定业务字段列表改为插件显式声明、运行时统一校验的有界事实信封。
- 为响应协议增加通用的结构化澄清元数据，支持选择项、槽位补充和有限的后续输入状态。
- 将澄清状态投影到 `BehaviorContext`，并在每次状态变化后异步保存到 SQLite。
- 更新语义抽取、兜底回复和普通回复提示词，使模型使用当前问题、可信事实和待澄清状态，不依赖业务关键词或原始聊天历史。
- 增加跨业务端到端测试，覆盖事实追问、数字选项、压缩、SQLite 恢复、流式/非流式一致性和失败安全边界。
- 更新 `docs/` 技术方案，明确通用事实信封、澄清状态生命周期和恢复语义。

## Capabilities

### New Capabilities

- 无。该变更扩展已有结构化会话上下文能力，不新增独立能力边界。

### Modified Capabilities

- `structured-model-context`: 允许插件显式声明通用可信事实，并持久化/传递结构化澄清状态，使后续短输入可以基于事实继续回答。
- `behavior-state`: 扩展可恢复的 pending 状态以承载经过边界校验的澄清选项，并保持事件投影、完整性哈希和压缩约束。

## Impact

- 影响 `@iar/contracts` 的 BehaviorContext、响应和事实契约。
- 影响运行时上下文投影、事件载荷和 SQLite 快照恢复。
- 影响 agent sandbox 的插件输出、兜底回复、模型提示词及测试夹具。
- 不改变 Function → Plugin 路由、JEV/Intent Model 决策结果、授权和高风险确认边界。
- 不保存原始聊天历史作为模型决策上下文，也不允许澄清元数据直接授权副作用动作。
