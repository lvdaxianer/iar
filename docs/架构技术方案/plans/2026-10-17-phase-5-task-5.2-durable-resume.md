# Phase 5 Task 5.2 Durable Resume Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 实现 Temporal-compatible 的 durable WorkflowRuntime adapter，持久化 Workflow step、Policy/Action 幂等关联和结果，使 worker 丢失后可从最后持久步骤恢复且不重复执行副作用。

**Architecture:** `DurableWorkflowRuntime` 复用 `LocalWorkflow` 的状态转移、Policy Gate、confirmation 和 Action executor 边界，不复制本地 Workflow 语义。每次可观察变更以 `DurableWorkflowSnapshot` 原子保存到注入的 `DurableWorkflowStore`；Action 在调用 executor 前先保存 pending step，完成后再保存结果。新 runtime 从 step 历史重建本地状态，已完成 Action 先重新经过 Policy Gate，再直接重放持久结果；pending Action fail-closed 为 `durable_action_in_progress`，避免未知副作用被重复调用。

**Tech Stack:** TypeScript 7、NodeNext、Node.js test runner、`@iar/workflow` 的 LocalWorkflow/PolicyGate/EventEnvelope、可注入内存 store。

test('durable runtime 持久化 start/transition step 并在新 worker 恢复最后步骤', async () => {

- [x] **Step 1: Define serializable durable records**

在 `types.ts` 增加：

```typescript
export type DurableStepOperation = 'start' | 'transition' | 'confirm' | 'execute' | 'fail' | 'retry' | 'timeout' | 'cancel' | 'resume';
export type DurableStepStatus = 'pending' | 'completed';
export type DurableExecuteRequest = Omit<ExecuteRequest, 'executor'> & { stepId: string };
export type DurableActionRecord = {
  request: DurableExecuteRequest;
  status: 'pending' | 'completed';
  outcome?: WorkflowResult<ActionResult>;
};
export type DurableStepRecord = {
  stepId: string;
  sequence: number;
  operation: DurableStepOperation;
  status: DurableStepStatus;
  data: DurableStepData;
};
export type DurableWorkflowSnapshot = {
  version: number;
  run: WorkflowRun;
  steps: DurableStepRecord[];
  actions: DurableActionRecord[];
  events: EventEnvelope[];
  nextEventSequence: number;
};
export interface DurableWorkflowStore {
  load(runId: string): Promise<DurableWorkflowSnapshot | undefined>;
  create(snapshot: DurableWorkflowSnapshot): Promise<boolean>;
  save(snapshot: DurableWorkflowSnapshot, expectedVersion: number): Promise<void>;
}
```

`DurableStepData` 必须是 start/transition/confirm/execute/fail/retry/timeout/cancel/resume 的显式 discriminated union；不得保存 executor function、secret 或 raw prompt。`DurableWorkflowRuntimeOptions` 扩展 v1 adapter 配置，要求 `DurableWorkflowRequirement` 与 start 的 workflowId 一致。

- [x] **Step 1: Implement start/get/transition persistence**

`start` 先验证 durable admission 和 WorkflowDefinition，再调用 `LocalWorkflow.start`，通过原子 `create` 保存 `workflow.started` 事件和 `start` step；重复 runId 返回 `workflow_exists`。`get` 从 store 读取深拷贝；`transition` 先确保 runtime 已 hydrate，调用 LocalWorkflow 后通过 expectedVersion CAS 保存新的 `WorkflowRun`、新事件和 completed step。

- [x] **Step 2: Implement action pending/completed persistence**

`execute(request, executor)` 先校验 request/executor，再对当前 confirmation 调用 `PolicyGate.evaluate`；拒绝不得写 step。对新 idempotency key 先保存 pending execute step，再调用 `LocalWorkflow.execute`；结果通过 Action Schema 后保存 `DurableActionRecord`、completed step 和 `action.started/action.completed/action.failed` 关联事件，Action input/output 只保存稳定摘要。已有 completed record 只重跑 Policy Gate 并返回深拷贝结果和 `action_duplicate`；pending record 返回 `durable_action_in_progress`，绝不调用 executor。

- [x] **Step 3: Implement retry/cancel/timeout/fail/resume**

这些操作只委托给 `LocalWorkflow` 的同名方法；成功后追加对应 completed step 并保存快照。终态、未知 run、非 retryable waiting 等稳定拒绝必须原样保留，不能把失败状态改写成成功。

- [x] **Step 4: Implement worker-loss hydration**

新 runtime 首次访问 run 时创建新的 LocalWorkflow，并按 sequence 重放 start、transition、confirm、execute、fail、retry、timeout、cancel、resume；每一步都检查返回结果，任何失败都返回 `durable_snapshot_invalid`；execute 只使用持久 ActionResult 的无副作用重放器，pending action 不重放。hydrate 完成后以 store snapshot 的 events 为事实源，并为后续新事件分配不重复的 durable event id。
