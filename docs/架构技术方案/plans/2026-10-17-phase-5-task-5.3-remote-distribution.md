# Phase 5 Task 5.3 Remote Distribution Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 实现带 Ed25519 签名、版本/依赖兼容检查、能力变更审批和可回滚审计记录的远程插件分发适配器。

**Architecture:** 新增独立 `@iar/plugin-distribution` 包，不改变 `PluginHost` 的本地生命周期和 `PolicyGate` 语义。分发器先验证签名和 Manifest 契约，再检查版本、依赖与 capability diff；安装/升级通过注入的 `PluginHost` 提交，升级失败或显式回滚恢复上一个不可变 Manifest，并保留完整审计记录。签名覆盖规范化 Manifest、bundle digest、版本和依赖字段，防止只替换包体或权限字段。

**Tech Stack:** TypeScript 7、Node.js `crypto` Ed25519、`@iar/contracts`、`@iar/plugin-host`、Node test runner、内存审计 store。

### Task 2: Implement atomic install/upgrade/rollback distribution service

**Files:**

- Create: `packages/plugin-distribution/src/distributor.ts`
- Modify: `packages/plugin-distribution/src/index.ts`

- [x] **Step 1: Add failing lifecycle tests**

  Verify `RemotePluginDistributor.install`, `.upgrade`, and `.rollback` use a supplied `PluginHost`, reject invalid artifacts before host mutation, require explicit capability approval for additions, reject incompatible versions/dependencies, and preserve audit history. Assert an upgrade failure leaves the previous enabled record unchanged and rollback restores the previous exact Manifest version.

- [x] **Step 2: Implement injected store and transaction boundary**

  Implement `InMemoryDistributionStore` with immutable current/version history and append-only audit records. Implement distributor flow in this order: verify artifact → load current state → compatibility/dependency check → capability approval → `PluginHost.install` → enable only after install succeeds → atomically commit current/history/audit. On any failure, do not mutate current state; rollback must call Host lifecycle transitions and reinstall the recorded prior Manifest without deleting events.
