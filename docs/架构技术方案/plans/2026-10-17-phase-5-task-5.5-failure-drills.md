> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为 Phase 5 补齐 durable、远程分发、跨语言 ABI 和多租户控制面的故障演练，并用可重复的测试记录本地 Workflow 到 durable adapter 的迁移与回滚路径。

**Tech Stack:** TypeScript 7、Node.js `node:test`、`@iar/workflow`、`@iar/adapters-temporal`、`@iar/plugin-distribution`、`@iar/abi`、`@iar/control-plane`。

- [x] **Step 1: Write the failing drills**

  Add fixtures using the real `WorkflowDefinition`, `LocalWorkflow`, `DurableWorkflowRuntime`, `InMemoryDurableWorkflowStore` and `evaluateDurableAdmission`. Cover these exact scenarios:

  ```typescript
  test('short local workflow is not migrated while timer workflow migrates to durable runtime', async () => {
    const local = new LocalWorkflow();
    assert.equal(local.start(request('migration-run')).ok, true);
    assert.equal(evaluateDurableAdmission({ workflowId: 'migration-flow', reasons: [] }).admitted, false);
    assert.equal(evaluateDurableAdmission({ workflowId: 'migration-flow', reasons: ['timer'] }).admitted, true);
    const durable = runtime(store, 'migration-flow');
    assert.equal((await durable.start(request('migration-run'))).ok, true);
    assert.equal((await durable.get('migration-run')).value?.currentStep, 'start');
  });

  test('worker restart after CAS conflict resumes from the durable snapshot without duplicate events', async () => {
    const store = new InMemoryDurableWorkflowStore();
    const first = runtime(store, 'failure-flow');
    const second = runtime(store, 'failure-flow');
    await first.start(request('failure-run'));
    const [left, right] = await Promise.all([
      first.transition({ runId: 'failure-run', event: 'ready' }),
      second.transition({ runId: 'failure-run', event: 'ready' })
    ]);
    assert.equal([left, right].filter((result) => result.ok).length, 1);
    const recovered = runtime(store, 'failure-flow');
    assert.equal((await recovered.get('failure-run')).value?.currentStep, 'ready');
    assert.deepEqual((await store.load('failure-run'))?.steps.map((step) => step.operation), ['start', 'transition']);
  });

  test('migration rollback keeps local runtime available when durable admission or persistence fails', async () => {
    const local = new LocalWorkflow();
    assert.equal(local.start(request('rollback-run')).ok, true);
    const rejected = assert.throws(() => new DurableWorkflowRuntime({
      adapterName: 'temporal-compatible',
      adapterVersion: 'v1',
      requirement: { workflowId: 'rollback-flow', reasons: [] },
      store: new InMemoryDurableWorkflowStore()
    }));
    assert.match(String(rejected), /durable_requirement_invalid/);
    assert.equal(local.transition({ runId: 'rollback-run', event: 'ready' }).ok, true);
    assert.equal(local.get('rollback-run').value?.currentStep, 'ready');
  });
  ```

  Also assert that a pending Action after worker loss returns `durable_action_in_progress`, invokes no executor, and that a completed Action replays `action_duplicate` exactly once. Capture the operation sequence and side-effect counter in assertions rather than relying on log text.
