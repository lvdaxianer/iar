# IAR 官方参考资料与借鉴边界

本文档只记录公开官方资料及其对 IAR 的可借鉴部分。参考项目不是 IAR 的运行时依赖，IAR 只吸收与插件、生命周期、上下文压缩、类型化决策、Schema、API 和工作流相关的边界。

## 1. DeepSeek Harness

- 架构文档：[DeepSeek Harness Architecture](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md)
- 官方介绍：[DeepSeek Harness](https://www.deepseek.com/harness/en/)

### 可借鉴

- 将模型适配、工具注册、会话日志、Agent Loop 等能力放进可组合的插件树；
- 用插件上下文管理注册、依赖和生命周期；
- 用可撤销的注册机制减少插件卸载后的残留能力。

### IAR 边界

IAR 借鉴插件宿主和可组合生命周期，但不复制其编码 Agent、沙箱、交互界面或 Profile 语义。IAR 的核心抽象仍然是 `Function -> Plugin -> Workflow`，并要求功能级路由先于插件级选择。

## 2. Hermes Agent Plugins

- 官方插件文档：[Hermes Agent Plugins](https://hermes-agent.nousresearch.com/docs/user-guide/features/plugins)

### 可借鉴

- 用 Manifest 描述插件的工具、命令、事件钩子、上下文压缩、审批和传输能力；
- 通过能力声明和显式启用控制插件暴露面；
- 将插件版本、配置和运行时能力作为可审计信息。

### IAR 边界

IAR 采用 Manifest-driven capability discovery，但 Manifest 还必须声明所属 `functionId`、输入输出 Schema、风险等级和确认策略。插件的能力不能因为模型选择而自动扩大，安装和升级仍需经过宿主授权。

## 3. Pi Extensions 与 Compaction

- 扩展文档：[Pi Coding Agent Extensions](https://github.com/badlogic/pi-mono/blob/main/packages/coding-agent/docs/extensions.md)
- 压缩文档：[Pi Context Compaction](https://github.com/badlogic/pi-mono/blob/main/packages/coding-agent/docs/compaction.md)

### 可借鉴

- 用生命周期事件让扩展参与输入、工具调用、会话恢复和上下文压缩；
- 用追加式状态记录保存扩展状态，并在恢复时重放；
- 压缩时显式记录保留边界，使用摘要加最近消息控制上下文大小；
- 允许扩展自定义压缩策略，但把压缩作为可观测的运行时事件。

### IAR 边界

IAR 不把对话摘要当作行为事实。`BehaviorContext`、事件日志、工作流步骤、插件版本、幂等键和确认状态必须独立保留；摘要只能生成 `ContextView`，且必须经过关键字段校验。

## 4. JEV

- 官方说明：[What is JEV?](https://jevmodel.org/what-is-jev/)
- 官方仓库：[jev-ai](https://github.com/jevmodel/jev-ai)

### 可借鉴

- 将离散选择、连续评分和 `noul`/拒绝作为一等决策结果；
- 让模型输出类型化结果，由应用程序负责最终解释、权限检查和副作用；
- 使用候选集合约束决策空间，降低开放式文本生成带来的执行风险。

### IAR 边界

JEV 在 IAR 中是 `DecisionProvider`，只负责 `function.select`、`plugin.select` 以及必要的评分/拒绝判断。它不负责自然语言生成、长文本摘要、插件执行或审批授权。IAR 必须处理阈值、`needs_clarification`、权限和审计。

## 5. DeepSeek Tool Calls

- 官方文档：[Tool Calls](https://api-docs.deepseek.com/guides/tool_calls/)

### 可借鉴

- 模型只提出结构化工具调用，应用程序负责实际执行；
- 使用严格的 JSON Schema 描述工具参数；
- 工具结果回传模型前后都要经过宿主程序的校验。

### IAR 边界

IAR 的插件调用比普通工具调用多一层 Function 归属、能力授权、Policy Gate、确认和 Workflow 状态。模型提出的 `pluginId`、参数和动作都不能绕过这些运行时检查。

## 6. Fastify

- 插件机制：[Fastify Plugins](https://fastify.dev/docs/latest/Reference/Plugins/)
- 校验与序列化：[Validation and Serialization](https://fastify.dev/docs/latest/Reference/Validation-and-Serialization/)
- TypeScript：[Fastify TypeScript](https://fastify.dev/docs/latest/Reference/TypeScript/)

### 可借鉴

- 用插件封装可复用的 HTTP 能力、装饰器和生命周期钩子；
- 复用 JSON Schema 做请求校验和响应序列化；
- 在 TypeScript 中保持 Schema、类型和路由定义的一致性。

### IAR 边界

Fastify 只作为 API Adapter，不定义 IAR 的 Function 路由和插件选择。IAR 的核心运行时可以脱离 HTTP 运行，Embedded SDK、Sidecar 和 Service 共享同一套 contracts。

## 7. Temporal

- 官方 TypeScript 文档：[Temporal TypeScript SDK](https://docs.temporal.io/develop/typescript)

### 可借鉴

- 将确定性 Workflow 与具有副作用的 Activity 分离；
- 使用持久化执行、超时、取消和重试支撑长流程；
- 通过明确的工作流边界恢复中断的动作。

### IAR 边界

Temporal 是可选的 `WorkflowRuntime` Adapter，不是 MVP 的必需依赖。IAR 先使用基于事件日志的本地确定性状态机，只有在出现长时间运行、跨服务协调或复杂补偿需求时再接入 Temporal。插件的 Function 归属、Policy 和确认逻辑仍由 IAR 管理。

## 8. 借鉴关系总结

| 参考项目 | IAR 借鉴 | IAR 不直接继承 |
| --- | --- | --- |
| DeepSeek Harness | 插件树、注册表、可撤销生命周期 | 编码 Agent、沙箱、Profile |
| Hermes Agent | Manifest、能力声明、显式启用 | 其 Agent 命令和产品级工具集合 |
| Pi | 生命周期事件、追加状态、显式压缩边界、通用 Agent 循环（未命中兜底委托） | 面向编码会话的 compaction 语义、编码工具集合 |
| JEV | Choice/Score/Noul 类型化决策 | 文本生成、执行授权 |
| DeepSeek Tool Calls | Schema 工具调用、应用执行 | 直接把工具调用当成完整路由 |
| Fastify | HTTP 插件、Schema 校验、序列化 | 业务路由和插件决策 |
| Temporal | Durable Workflow、Activity 隔离 | MVP 的默认运行时依赖 |
