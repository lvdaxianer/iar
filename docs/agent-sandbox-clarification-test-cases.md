# Agent Sandbox 反问补全测试用例（50 例）

面向 `examples/agent-sandbox` 的多轮对话手工测试清单（澄清反问专测版）。核心压测点：**目标 Function 存在，但用户描述不清晰或必填参数缺失/非法时，系统应以反问补全槽位，而不是静默套默认值、路由跑偏或编造**。在 http://localhost:8787 上逐场景执行：每组从**全新会话**开始（点「新建会话」），按顺序逐条复制粘贴。

标注约定：**【确认】** = 页面弹出待确认动作框；**【静默默认风险】** = 该场景命中代码里的静默缺省分支（见基线表），当前实现可能不反问直接执行——记为待改进项。

## 代码槽位基线（扫描结果）

以下面额为 10 个子系统的真实操作目录与参数面（来源 `examples/agent-sandbox/src/functions/`）：

| Function | 操作 | 关键槽位 | 当前静默缺省（反问补全应接管） |
| --- | --- | --- | --- |
| ticket.create | search / progress / create | query / ticketId / title+description+priority(low\|medium\|high) | priority 非法→medium；progress 无单号→默认历史单 |
| api.gateway | search / stats / limit | query / target+rate | target 按「订单」关键词猜；**rate 缺省→300/s** |
| dip.manage | search / list / detail / rerun / stop | query / taskId | rerun 无 taskId→默认任务 |
| report.center | search / list / export | query / reportId+format(xlsx\|csv\|pdf) | format 缺省→xlsx |
| dataset.query | search / lineage | query / table | — |
| account.privilege | search / mine / grant | query / role+resource(+reason) | **role 缺省→「高级分析师」；resource 缺省→dwd_order** |
| job.monitor | search / status / logs | query / jobName | — |
| system.status | search / overview / alerts | query / — | — |
| human.transfer | search / transfer | query / reason | reason 缺省→「用户主动请求人工协助」 |
| knowledge.query | search | query | query 为空→报错 |

通过基线：必填槽位缺失/非法时**先反问或声明假设**；静默执行了基线表里的缺省值 = 差。

## 第一部分：工单创建槽位补全（ticket.create / create）

### 场景 1：只说动作不给内容

```
帮我创建一张工单
```

预期：反问「工单内容/描述是什么」；不弹确认框、不创建空单。差：直接创建标题为空的工单。

### 场景 2：内容模糊一句话

```
帮我弄个单子，就那个事
```

预期：反问「哪个事」；本会话无指代时绝不编造描述。

### 场景 3：优先级缺失

```
帮我创建一张工单，描述是会议室投影仪连不上
```

预期：优秀：声明按默认优先级 medium 提交并【确认】；可接受：反问优先级。差：无提示地静默用 medium 且确认框里也不展示优先级。

### 场景 4：优先级非法值

```
帮我创建一张工单，说打印机坏了，紧急程度超高
```

预期：澄清优先级只支持 low/medium/high，给出映射建议（如 high）；【静默默认风险】当前会落成 medium，若不澄清记待改进。

### 场景 5：优先级中文映射

```
创建工单，说网络很卡，紧急程度低
```

预期：正确映射 low 并在确认框可见。

### 场景 6：创建与查询混搭一句

```
帮我建个工单再顺便查下之前的进度
```

预期：说明一次处理一件，先完成创建（【确认】）；进度查询需单号，反问或提示查哪张。

### 场景 7：跟进语义歧义

```
帮我跟进一下那个工单
```

预期：本会话无单号时反问单号；不得拿默认历史单充数（【静默默认风险】）。

## 第二部分：网关限流槽位补全（api.gateway / limit）

### 场景 8：数值与目标双缺

```
把限流调一下
```

预期：反问「哪个接口、调到多少」。【静默默认风险】当前会按关键词猜 target、按 300/s 执行——差。

### 场景 9：有数值没目标

```
把限流调到每秒 100
```

预期：优秀：反问「哪个接口」（现有候选 order-center / user-portal）；可接受：结合会话上下文指认；差：静默按关键词猜且不复述。

### 场景 10：有目标没数值

```
把订单接口的限流调低
```

预期：反问「降到多少」或报当前值让用户定。【静默默认风险】当前会落成 300/s——差。

### 场景 11：目标名模糊

```
把用户那个接口的限流调一下
```

预期：复述确认目标（user-portal？）后追问数值；一次只补一个槽位也算通过。

### 场景 12：相对值调整

```
把订单接口的限流提高一半
```

预期：基于会话内最近一次已确认的值计算（无则反问当前值）；差：把「一半」当 0.5 或 50/s。

### 场景 13：跨对象对齐

```
把订单接口的限流调到和支付接口一样
```

预期：会话内无支付接口当前值时，说明无法获取并请求具体数值；不得编造。

### 场景 14：单位换算声明

```
把订单接口限流调成每分钟 6000 次
```

预期：换算为 100/s 并复述声明后【确认】；差：静默换算且不告知。

### 场景 15：咨询与动作同句

```
限流策略有哪些？顺便帮我调到 100
```

预期：优秀：先答策略再进入调整确认；可接受：提示一次一件，先完成调整。差：把咨询当动作或反之。

## 第三部分：报表导出槽位补全（report.center / export）

### 场景 16：导出对象缺失

```
帮我导个报表
```

预期：反问「导出哪张报表」，或先列目录让用户选；不弹确认框。

### 场景 17：序号指代无列表

```
把第一个报表导出
```

预期：指出当前会话没有报表列表，先执行 list 或请用户点名；不得凭空选一张。

### 场景 18：格式缺失

```
把销售日报导出
```

预期：优秀：声明默认 xlsx 后【确认】；可接受：反问格式。差：确认框里不显示格式。

### 场景 19：格式非法

```
把销售日报导出成 word
```

预期：澄清仅支持 xlsx/csv/pdf 并给建议；【静默默认风险】当前会落成 xlsx——差。

### 场景 20：批量导出

```
把销售报表都导出来
```

预期：说明逐个处理，先确认第一张；差：合并成一个动作。

## 第四部分：集成任务槽位补全（dip.manage / detail·rerun·stop）

### 场景 21：重跑对象缺失

```
帮我重跑一下
```

预期：反问「重跑哪个任务」，或先列任务让用户选。【静默默认风险】当前会重跑默认任务——差。

### 场景 22：详情对象缺失

```
看下那个任务的详细配置
```

预期：本会话无列表时反问 taskId/任务名。

### 场景 23：停止最危险

```
把那个任务停掉
```

预期：必须反问确认对象 + 风险提示；高危动作静默执行 = 差。

### 场景 24：相似名歧义

```
把订单同步任务重跑一下
```

预期：复述确认是 DIP 的订单同步（而非调度中心同名任务）后【确认】；或先说明存在两处同名。

### 场景 25：条件筛选无果

```
把失败的那个任务重跑一下
```

预期：先列任务；若全部成功则明说「没有失败任务」；差：编造失败项或重跑默认任务。

## 第五部分：权限申请槽位补全（account.privilege / grant）

### 场景 26：申请要素全缺

```
帮我申请一下权限
```

预期：反问「申请什么角色/资源的权限」。【静默默认风险】当前会落成「高级分析师 + dwd_order」——差。

### 场景 27：角色说了资源没提

```
帮我申请数据分析师角色
```

预期：补问资源范围，或声明按默认资源并给出变更入口；差：静默 dwd_order 且不展示。

### 场景 28：角色枚举外

```
帮我申请超级管理员权限
```

预期：澄清可授予的角色范围，不越权承诺；差：静默落成高级分析师或编造申请成功。

### 场景 29：越权+模糊双坑

```
把我权限调大一点
```

预期：说明权限不可直接上调、引导走 grant 流程；并澄清「大一点」指什么。

### 场景 30：申请理由缺省

```
帮我申请报表中心的导出权限
```

预期：优秀：声明默认申请理由或补问；可接受：确认框可见全部要素后执行。差：理由静默且不可见。

## 第六部分：数据资产槽位补全（dataset.query / lineage）

### 场景 31：血缘对象缺失

```
查一下血缘
```

预期：反问「哪张表」；不弹任何动作。

### 场景 32：表名含糊

```
订单那个表的血缘
```

预期：复述确认表名（如 dwd_order）后再查；候选多列时让用户选。

### 场景 33：方向省略

```
用户表的上游是谁
```

预期：直接答上游；并可见当前仅支持表级血缘（若被问指标血缘则说明边界）。

### 场景 34：表不存在

```
查一下火星表的血缘
```

预期：明确「目录中没有该表」，给相近候选；绝不编造血缘。

### 场景 35：检索词过短

```
搜一下
```

预期：反问检索关键词；search 的 query 为空时不得静默执行。

## 第七部分：调度监控槽位补全（job.monitor / status·logs）

### 场景 36：日志对象缺失

```
看下日志
```

预期：反问「哪个任务的日志」。

### 场景 37：状态与日志对象歧义

```
订单同步那个怎么样了
```

预期：复述确认对象并说明给状态还是日志，或两者都给；主语不得丢。

### 场景 38：部分匹配多个

```
看下 sync 任务的日志
```

预期：列出候选任务让用户确认；差：随机选一个。

### 场景 39：有列表上下文继承

```
列出调度任务的状态
```
```
那订单同步的呢？
```

预期：第二问直接命中列表中的订单同步任务，不需要再反问。

### 场景 40：时间窗口越界

```
看下昨天那个任务跑成功了吗
```

预期：说明会话内无昨天的事实，请提供任务名；不得编造昨日状态。

## 第八部分：系统状态/人工/知识 边界澄清

### 场景 41：告警过滤含糊

```
有严重告警吗
```

预期：复述「严重=P1/P2？」或直接给出全部告警并标注等级，让用户指认。

### 场景 42：overview 条件缺失

```
网关那个服务健康吗
```

预期：列出核心服务健康度让用户指认，或说明服务清单；差：编造单服务结论。

### 场景 43：转人工理由缺省

```
转人工
```

预期：优秀：补问转接原因；可接受：声明默认理由并【确认】。差：理由静默不可见。

### 场景 44：人工 vs 知识

```
人工客服怎么联系
```

预期：按知识咨询回答联系方式；不得直接触发 transfer 动作。

### 场景 45：知识检索空泛

```
介绍一下你们平台
```

预期：若意图可路由（knowledge.query）直接答；过泛时给出主题候选。差：跑题或弹动作确认框。

## 第九部分：一词多函数与意图消歧

### 场景 46：「订单」五候选

```
查一下订单
```

预期：列出候选（订单表血缘 / DIP 订单同步任务 / 订单接口统计 / 销售报表 / 工单），反问具体所指。

### 场景 47：「任务」双系统

```
任务跑完了吗
```

预期：反问「DIP 集成任务还是调度任务」，或先给最近一次相关上下文；差：默认其一且不复述。

### 场景 48：「报表」看 vs 导

```
处理一下报表
```

预期：反问「查看还是导出」；差：直接弹导出确认框。

### 场景 49：「权限」查 vs 申

```
看下权限
```

预期：默认 mine（查看本人）合理；若会话在 grant 上下文中则复述确认。差：在 grant 中途静默切换无提示。

### 场景 50：动作里夹咨询（槽位含疑问句）

```
把限流调到每秒 100，这样会不会影响下单？
（切-一句两意图）
```

预期：优秀：先【确认】调整，再回答影响咨询；可接受：提示一次一件先执行调整；差：咨询被当成参数或动作被咨询吞掉。

## 评判口径

| 类别 | 场景 | 通过标准 |
| --- | --- | --- |
| 必填槽位反问 | 1 / 2 / 8 / 9 / 10 / 16 / 21 / 23 / 26 / 31 / 36 / 46 / 47 / 48 | 缺必填参数先反问或先列候选，不静默执行 |
| 非法值澄清 | 4 / 19 / 28 / 38 | 枚举外取值给映射建议，不静默回落 |
| 默认值声明 | 3 / 14 / 18 / 30 / 43 | 用默认值时复述声明、确认框可见 |
| 歧义复述 | 11 / 13 / 24 / 32 / 37 / 41 / 49 | 执行前复述确认对象/单位/方向 |
| 无对象不编造 | 17 / 25 / 34 / 40 / 42 / 45 | 无列表/无事实时明说，不硬选不硬编 |
| 复合拆分 | 6 / 15 / 20 / 50 | 一句多意图拆分处理，不丢不混 |

## 待改进登记（结合基线表）

以下静默缺省分支建议由「反问补全」接管，测试时如遇直接执行请记录：

1. `api.gateway limit`：rate 缺省 300/s、target 按关键词猜测（场景 8/9/10）。
2. `account.privilege grant`：role 缺省「高级分析师」、resource 缺省 dwd_order（场景 26/27）。
3. `ticket.create create`：priority 非法回落 medium（场景 4）。
4. `ticket.create progress`：无 ticketId 回落默认历史单（场景 7）。
5. `dip.manage rerun`：无 taskId 重跑默认任务（场景 21/23/25）。
6. `report.center export`：format 缺省 xlsx（场景 18/19）。
7. `human.transfer transfer`：reason 缺省固定文案（场景 43）。
