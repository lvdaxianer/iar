# Phase 5 Task 5.4 ABI and Control Plane Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 实现版本化跨语言 JSON ABI 和 tenant-bound control plane，使远程插件安装、升级、启用、禁用、回滚、审计继续遵守同一 Manifest、Schema、tenant、Policy Gate 和 PluginHost 生命周期契约。

**Architecture:** 新增独立 `@iar/abi` 包定义 JSON-safe、版本化的 control-plane request/response 和 ABI compatibility matrix；所有边界输入先做 allow-list、Manifest/Schema 和 tenant 校验，再进入 control-plane。新增 `@iar/control-plane` 包按 tenant 隔离 `PluginHost`、`RemotePluginDistributor` 和审计视图，授权回调必须在任何 Host 访问前通过，control plane 不复制 Policy Gate 语义，只调用注入的 policy/authorization boundary。

**Tech Stack:** TypeScript 7、Node.js JSON serialization、`@iar/contracts`、`@iar/plugin-host`、`@iar/plugin-distribution`、Node test runner。

- [x] **Step 1: Add failing tenant and lifecycle tests**

  Build two independent tenant contexts with independent `PluginHost`, `RemotePluginDistributor`, and audit store. Assert install/inspect/upgrade/enable/disable/rollback are authorized by `{ tenantId, actorId, environment }`, foreign tenant plugin IDs return stable `tenant_access_denied` before Host access, and malformed ABI requests return stable errors. Assert Policy Gate callback is required for capability expansion and high-risk operations; the control plane must not grant capabilities or bypass the existing router/policy semantics.

- [x] **Step 2: Implement tenant-bound store and operation dispatcher**

  Implement `TenantControlPlane` with `Map<tenantId, TenantRuntime>` created only after `authorize(context, operation)` succeeds. Each tenant runtime owns one `PluginHost`, one `RemotePluginDistributor`, and tenant-filtered audit projection. Dispatch exact operations:

  ```ts
  type ControlPlaneOperation = 'plugin.install' | 'plugin.upgrade' | 'plugin.enable' | 'plugin.disable' | 'plugin.rollback' | 'plugin.inspect' | 'plugin.audit';
  type PolicyDecision = { allowed: boolean; reasonCode?: 'policy_denied' | 'capability_approval_required' };
  ```

  `plugin.install`/`upgrade` call distribution verification and policy approval; `enable`/`disable`/`rollback` call only the tenant-owned Host/distributor. Every response includes protocol version, request/trace/tenant IDs, stable schema version, safe data or error, and never includes private keys, raw signatures, bundle payloads, or another tenant’s records.

  Run: `npm test -- --run tests/distribution/control-plane.test.ts tests/compatibility/abi-compatibility.test.ts`
