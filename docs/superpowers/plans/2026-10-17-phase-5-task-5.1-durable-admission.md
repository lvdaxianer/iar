# Phase 5 Task 5.1 长流程准入与 WorkflowRuntime 合约 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建立一个版本化的 `WorkflowRuntime` 适配器合约和长流程准入门槛，使短动作继续走 `LocalWorkflow`，只有明确声明 timer、cross-service 或 compensation 需求的流程才可进入 durable 适配器。

**Architecture:** 在 `packages/adapters/temporal/` 新增 framework-independent 的 durable contract 和 admission policy。`WorkflowRuntime` 以既有 `WorkflowRequest`、`WorkflowRun`、`WorkflowResult` 为输入输出边界，并用 `DurableWorkflowRequirement` 表达长期运行需求；Task 5.1 只提供入口判定和一个不执行副作用的 contract adapter，真实持久化、恢复、重试和取消留给 Task 5.2。现有 `LocalWorkflow` 不修改，调用方必须显式选择本地或 durable runtime。

**Tech Stack:** TypeScript 7、NodeNext、Node.js test runner、现有 `@iar/workflow` 类型和 npm workspace。

- [x] **Step 1: Define the public contract**

在 `types.ts` 定义以下精确类型：

```typescript
export type DurableRequirementReason = 'timer' | 'cross_service' | 'compensation';

export type DurableWorkflowRequirement = {
  workflowId: string;
  reasons: readonly DurableRequirementReason[];
  rationale?: string;
};

export type DurableAdmissionDecision =
  | { admitted: true; workflowId: string; reasons: readonly DurableRequirementReason[] }
  | { admitted: false; reasonCode: 'durable_requirement_missing' | 'durable_requirement_invalid' };

export type WorkflowRuntimeContract = {
  readonly adapterName: string;
  readonly adapterVersion: 'v1';
  start(request: WorkflowRequest): WorkflowResult<WorkflowRun>;
};

export type WorkflowRuntimeOptions = {
  adapterName: string;
  adapterVersion: 'v1';
};
```

其中 `WorkflowRequest`、`WorkflowResult` 和 `WorkflowRun` 从 `@iar/workflow` 导入；不得复制本地 Workflow 状态类型。

- [x] **Step 2: Implement deterministic admission**

在 `admission.ts` 实现 `evaluateDurableAdmission(requirement)`：

1. `workflowId` 必须是非空字符串；`reasons` 必须是非空数组。
2. 所有 reason 必须属于三项白名单；未知 reason 返回 `durable_requirement_invalid`。
3. 通过校验后返回 `admitted: true`，去重并按固定顺序 `timer`、`cross_service`、`compensation` 返回 reasons。
4. 空 reasons 返回 `durable_requirement_missing`。

该函数只能做内存校验，不访问网络、数据库或环境变量。

- [x] **Step 3: Implement a non-side-effect contract runtime**

在 `contract-runtime.ts` 实现 `ContractWorkflowRuntime`：

```typescript
public start(request: WorkflowRequest): WorkflowResult<WorkflowRun> {
  if (!this.isValidRequest(request)) return { ok: false, reasonCode: 'workflow_request_invalid' };
  return { ok: false, reasonCode: 'durable_adapter_not_implemented' };
}
```

它只验证 `runId`、`definition` 的稳定存在和 adapter 版本配置，不创建本地运行态、不执行 Action、不绕过 Policy Gate；Task 5.2 将在同一 contract 上替换为真正的持久化实现。所有 public class/function 加中文 JSDoc、`@author lvdaxianer@yeah.net` 和 `@date 2026-10-17`。
